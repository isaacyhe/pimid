[0;32m1. Compute Power is EQUAL across all architectures:[0m
   └─ All have 64 compute units @ 2 GFLOPS = 128 GFLOPS total
   └─ Pure compute time is IDENTICAL

[0;32m2. Data Movement is DIFFERENT:[0m
   └─ Subarray-PIM: Data already in subarray (26ns latency)
   └─ Bank-PIM: Cross-bank access (40ns latency)
   └─ Chip-PIM: Cross-chip routing (60ns latency)
   └─ CPU: Through memory controller + system bus (100ns latency)

[0;32m3. Parallelism vs Locality Trade-off:[0m
   └─ Subarray-PIM: 64 parallel units, but limited local memory (512KB each)
   └─ Bank-PIM: 16 parallel units, larger local memory (2MB each)
   └─ CPU: 1 unit, full memory access but high data movement cost

[0;32m4. Energy Efficiency Hierarchy:[0m
   └─ Subarray: 1 pJ/byte (just sense amp)
   └─ Bank: 2 pJ/byte (+ bank switching)
   └─ Chip: 5 pJ/byte (+ on-chip routing)
   └─ Rank: 10 pJ/byte (+ I/O drivers)
   └─ CPU: 20 pJ/byte (+ system bus + LLC)

[0;32m5. Best Architecture Depends on Workload:[0m
   └─ Data fits in subarray? → Subarray-PIM wins
   └─ Needs bank-level data? → Bank-PIM wins
   └─ Random access patterns? → Coarser PIM or CPU may be better

[0;35m[1mBottom Line:[0m
  PIM's advantage comes from REDUCING DATA MOVEMENT, not faster compute!
  Closer to memory = lower latency + lower energy + higher effective bandwidth
